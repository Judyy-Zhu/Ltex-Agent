Checker feedback quick reference, shared by Lean and Litex. Read read_docs("feedback") for the complete language-specific field guide.
The first check response block contains controller metadata; the next contains native diagnostics. Read both.
passed is this machine check's result. Successful final checking and submission gates determine automatic task success; semantic review is optional metadata, never a prerequisite. This does not independently certify source fidelity. controller_error describes budget, protocol, foundation or process problems, not a mathematical counterexample.
Incremental feedback.frames contains received native responses for newly checked source. Native fields are not rewritten into another language's schema. Empty frames may mean accepted-source caching, initialization/replay/protocol failure, or a candidate sent before a response timeout. Consult passed, controller_error, session and item_tracking; an empty frame list does not prove that no candidate was sent.
Litex: inspect native.run_result, statement_results, errors, session_terminated and termination. phase, category, message and obligation locate failed obligations. statement_index is a zero-based index within the native turn, not a source line number.
Lean: inspect native.messages severity/data/pos/endPos, sorries and env. environment_transition.adopted_returned_env records whether the controller adopted the returned environment. Repair the current declaration after errors or unsolved goals; returned env alone is not success.
Ordinary failures preserve the earlier accepted library. Editing an accepted fragment invalidates its dependent suffix; recheck predecessors as directed. Hard errors/timeouts can trigger restart and replay. Replay is not a new proof attempt.
feedback_truncated=false means that the adapter did not trim the response, not that the kernel found every possible error. Use read_library(["receipt:check-0001"]) for full_receipt, and read_library(["submission_gate"]) after submission-gate failure.
Use one file per logical definition/proof. The first write_source needs stable item_id/item_kind; keep the ID when repairing. Read read_docs("items") and read_docs("feedback"). item_tracking reports the current item; read_library(["retry_stats"]) reports all items. The controller records retries; do not supply or reset counts yourself.
