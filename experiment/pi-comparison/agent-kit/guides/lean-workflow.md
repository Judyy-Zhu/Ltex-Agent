# Sequential library building and recovery in Lean

Read read_docs(feedback), read_docs(items), task.json, the current source TXT, foundation.json and seed-interface.json, then inspect the own-language library index. Every task is text-only; do not request images. read_library(["entry:TASK_ID"]) retrieves an increment. Published entries have passed the automatic machine gates and may be used immediately, even when optional semantic review is pending. Do not wait for a human review. Prove missing predecessors within the current budget; do not add them as assumptions.

Save each complete definition/theorem in its own fragment. First write_source supplies stable item_id/item_kind; repairs retain the ID. check(incremental) enters the same REPL. A failed command does not adopt returned env; the previous successful environment survives. Close a complete namespace in the same fragment, or open/close it across scope fragments; the final module must balance scopes. Use cases, by_cases, rcases, constructor, intro and by_contra for logical structure. Natural-number induction uses induction and must preserve source positivity/greater-than-one restrictions. Reuse results via exact, apply, rw or have with all premises.

Editing accepted source invalidates dependent suffixes; recheck predecessors as directed. After hard errors, the tool restarts and replays the accepted journal. Failed replay blocks continuation. Final checking uses a fresh process without closing the writing REPL.

Write interfaces.json with public names, exact types, expanded meanings, source clauses and encoding bridges. Use write_source with path="final.lean", content="", base="accepted" to assemble the frozen seed, predecessors and accepted current fragments. The complete final module must exactly match this assembly; no unchecked code may be added. Assembly proves no new fact. Call check(final), then submit, reserving time for the independent declaration/axiom gate. Do not weaken types, hide extra premises or exploit degenerate cases to avoid the target.

Only complete submissions passing controller checks are published to the next task. Accepted fragments from failed tasks are not published. Each next task starts a new agent conversation inheriting the library, not the chat. read_library(["submission_gate"]) shows the gate result. All failures and reading costs remain measured.
