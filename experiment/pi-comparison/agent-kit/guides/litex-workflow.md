# Sequential library building and recovery in Litex

Read read_docs(feedback), read_docs(items), task.json, the current source TXT, foundation.json and seed-interface.json, then inspect the own-language library index. Every task is text-only; do not request images. read_library(["entry:TASK_ID"]) retrieves an increment. Published entries have passed the automatic machine gates and may be used immediately, even when optional semantic review is pending. Do not wait for a human review. Prove missing predecessors within the current budget; do not add them as assumptions.

Save each complete top-level definition/theorem as its own incremental fragment and call check(incremental) in the same native Session. First write_source supplies stable item_id/item_kind; repairs retain the ID. Indentation is part of theorem syntax; do not split steps within one proof into unrelated top-level requests. Follow the checked prop, forall, exist, witness and thm forms. Resolve each reported premise, domain obligation and conclusion using native diagnostics, not guessed Lean-style tactic names. Confirm supported rules and domains before using cases, contradiction or recursion; they cannot be replaced by unverified facts.

Editing accepted source invalidates dependent suffixes; recheck predecessors as directed. After hard errors, the tool restarts and replays the accepted journal. Failed replay blocks continuation. Final checking uses a fresh process without closing the writing Session. Read complete statement_results, including proof_method/stores/infers, errors and termination fields. Source-line mappings accompany the native feedback.

Write interfaces.json with public names, definition expansions, source clauses and encoding bridges. Use write_source with path="final.lit", content="", base="accepted" to assemble the frozen seed, predecessors and accepted current fragments. The complete final module must exactly match this assembly; no unchecked code may be added. Assembly proves no new fact. Call check(final), then submit, reserving time for the independent declaration gate. Do not introduce trust, unproved abstract predicates or axiom fallbacks.

Only complete submissions passing controller checks are published to the next task. Accepted fragments from failed tasks are not published. Each next task starts a new agent conversation inheriting the library, not the chat. read_library(["submission_gate"]) shows the gate result. All failures and reading costs remain measured.
