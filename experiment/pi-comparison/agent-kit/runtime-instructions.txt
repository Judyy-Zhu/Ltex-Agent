This is a source-to-library formalization-translation experiment with automatic machine acceptance. Passing the controller's final/submission checks is sufficient for task success and publication; do not wait for human review. Optional semantic annotations are recorded separately and never gate the primary score. check(incremental) uses the same persistent native session. check(final) verifies the complete file in a fresh process and preserves the writing session. Neither adapter silently falls back to whole-file incremental checking.

Save each complete top-level definition or theorem in a separate fragment. On the first write_source call, provide a stable item_id and item_kind, then call check(incremental). Keep the ID when repairing the same logical item. Leave accepted fragments unchanged unless a repair is necessary. Editing an accepted predecessor invalidates the dependent suffix; recheck it in the order reported by the tool.

Both native sessions initially load the frozen minimal seed and their own published predecessor library. Use read_library([]) for the index and read_library(["entry:TASK_ID"]) for individual increments. Read foundation.json, seed-interface.json and the seed source named by foundation.seed.input_path. GeoPoint, geo_point, geo_x, geo_y, geo_vec, geo_dot and geo_det are already provided; do not redeclare or change them. Euclid-specific circles, distances, triangles and propositions remain your work.

Lean loads approved imports and the seed once at REPL startup; incremental fragments must not import them again. Write interfaces.json first. Then use write_source with a separate final.lean or final.lit path, empty content and base="accepted" to assemble the seed, predecessor library and accepted current fragments into a complete module, and call check(final). The final module must exactly assemble accepted fragments; it cannot introduce unchecked code. Guides are available through read_docs topics core, basics, roots, workflow, domains, seed, feedback and items.

The listed seed is approved for development verification. A complete equivalence audit of transitive imports remains pending; this does not prevent the current development task. Seed declarations do not count as agent-completed Euclid tasks.

check first returns a common controller receipt, then native feedback. Litex preserves each complete Session JSON response, including statement_results, errors, session_terminated and termination. Lean preserves REPL messages, sorries and env, and reports whether it adopted the returned environment. Final checking preserves the respective file-verifier output. Read the diagnostics, not only passed. Use read_library(["receipt:check-0001"]) for an original receipt. Use task-specific prefixes or namespaces for new declarations to avoid foundation-name collisions.
